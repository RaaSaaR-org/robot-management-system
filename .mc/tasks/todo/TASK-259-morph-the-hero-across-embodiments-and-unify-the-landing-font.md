# Morph the hero across embodiments and unify the landing font

## Description

The TASK-258 hero showed one abstract CPU core. It should show the claim the platform makes — one intelligence, many bodies — by morphing real digital twins (Unitree G1 humanoid, Holybro X500 drone, Unitree Go2 quadruped) into each other. At the same time the landing page mixes three typefaces in its running text; normal text must use one.

## Details

**Current state:** `app/src/components/landing/heroEngine.ts` renders a CPU atom with orbital paths behind the copy. Labels, eyebrows, tags, values and captions across the landing page are set in JetBrains Mono, several at 6–9px.

### Frontend

- `heroEngine.ts` loads three Meshopt-compressed GLBs, samples the same number of surface points from each, and runs an 8 s cycle: hold the hardware, dissolve it voxel by voxel into pixels, fly the pixels to the next body, resolve. Losing one model keeps the others cycling; losing all keeps the poster.
- `heroEmbodiments.ts` holds the embodiment list and the pure timeline, so the sequence is testable without WebGL.
- `HeroScene.tsx` shows a static poster of all three (`hero-embodiments.webp`) until the engine is ready, and never loads 3D under `prefers-reduced-motion` — including when the preference changes at runtime.
- Typography rule for the landing page: **Inter** for all normal text (body, labels, eyebrows, tags, values, captions); **Archivo** for headlines only; **JetBrains Mono** only for code and machine output (install commands, the Agent Mode plan and halt line). No landing text below 10px.

### Assets

- `app/public/assets/landing/{g1,x500,go2}-twin.glb` + licenses + README; regenerated by `scripts/build-hero-model.py` from pinned upstream revisions (PX4 Gazebo Models, MuJoCo Menagerie — both BSD-3-Clause).

**Key files:** `app/src/components/landing/{HeroScene.tsx,HeroSection.tsx,heroEngine.ts,heroEmbodiments.ts,hero.css,landing-theme.css,platform.css,embodied-loop.css,HonestySection.tsx,SovereigntySection.tsx,SafetyRobotScene.tsx}`, `app/src/index.css`, `app/e2e/landing-hero.spec.ts`, `scripts/build-hero-model.py`, `app/public/assets/landing/`.

## Acceptance Criteria

- [x] The hero cycles humanoid → drone → quadruped → humanoid with no controls, and the caption names the visible embodiment.
- [x] Reduced motion, WebGL unavailable, all models unavailable and context loss each leave the full poster and working navigation; one missing model does not stop the rest.
- [x] All normal landing text uses Inter; mono appears only on code and machine output; no landing text is smaller than 10px.
- [x] No horizontal overflow and readable hero labels at 320, 390 and 768px.
- [x] Typecheck, landing unit tests and the Playwright e2e gate pass.

## Test Strategy

- `npx tsc` and `npx vitest run src/components/landing` in `app/`.
- `npx playwright test` in `app/` — `e2e/landing-hero.spec.ts` covers the cycle, motion preferences, context loss, asset failures, phone widths and the label font.
- Visual review at 320, 390, 768, 1280 and 1440px against the running app.

## Verification

- `npx tsc` clean; landing vitest 11/11; full Playwright gate 52/52 (`PLAYWRIGHT_PORT=4187`, because a foreign preview held :4173), including all seven `landing-hero.spec.ts` cases.
- Rendered-text audit of the whole landing page at 320, 390, 768 and 1440px: no font other than Inter or Archivo outside the install commands and the Agent Mode plan line, nothing under 10px, zero horizontal overflow.
- Review fixes on top of the hero work: 6–9px mono hero labels raised to ≥10px Inter; the halo ring no longer strikes through the scene heading; phone callouts wrap onto two lines clear of the twin; the right callout no longer clips past the viewport between 1101 and 1360px (checked at seven widths).
- Known follow-up, not fixed here: `go2-twin.glb` is 1.19 MB because `scripts/build-hero-model.py` skips decimation for `base_*` meshes (the body shell alone is ~88k triangles); decimating it would roughly halve the hero's 3D payload.
